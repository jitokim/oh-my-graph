### Fixed

- **`auto` no longer warns about a plan its own planner wrote, and a planned `result_matches` now also checks the exit code.** The planner prompt handed out `success_check` with `result_matches` alone, and a node that declares any check loses the exit-zero default it had with none, so the plan `auto` launched left that node's exit code unchecked and the `result_matches without exit_zero` lint warned about it. The prompt now pairs every `result_matches` it describes with `"exit_zero": true`, and after validation trusted code sets `exit_zero: true` on every planned node whose `success_check` has a `result_matches` and no `exit_zero`, including an explicit `false`. It only ever adds the guard: the pattern is unchanged, and a node with no `success_check` or one already setting `exit_zero` is left alone. The plan screen prints `note: node <id>: exit_zero: true added beside its result_matches (a planned check is never weaker than the exit code)` for each node it changed, and `graph.json` and the `--plan-only` plan carry the guard. A hand-written graph run with `run` is never rewritten and still gets the warning. ([#371](https://github.com/jitokim/oh-my-graph/issues/371))
