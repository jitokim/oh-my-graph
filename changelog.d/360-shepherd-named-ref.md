### Fixed

- **`merge-shepherd` tests the PR head it names, and two shepherds can run in one repo.** `verify` and `triage` no longer build their throwaway worktree from git's shared `FETCH_HEAD`, which a concurrent fetch (another shepherd, or the operator by hand) can repoint to another commit. Each reads the PR head SHA from `gh`, fetches it into the named, content-addressed ref `refs/omg-shepherd/pr-<N>/<sha>`, confirms the ref resolves to that SHA, and adds the worktree detached at the SHA itself, recording it in the per-worktree ref `refs/worktree/omg-shepherd-sha`. A new engine-run `success_check.verify` on each node fails unless the worktree's HEAD equals the PR's `headRefOid`, and an EXIT trap removes the worktree and deletes that run's ref whatever the check's result. `triage` now builds its worktree first, even for `TRIAGED 0`, pushes with `HEAD:refs/heads/<branch>`, and answers `BLOCKED` if GitHub's head is not its commit, so a legitimate push passes and a head someone else moved fails. The check runs only once the reply matches, so cleanup is split: on `FAIL` (verify) or `BLOCKED` (triage) the agent removes its own worktree and ref before answering, and on `PASS` or `TRIAGED` it leaves both for the engine check to compare and remove. Step 0 of the next attempt still clears any leftover. A run killed outright, or one that fetched but never built its worktree, can leave a ref behind: list them with `git for-each-ref refs/omg-shepherd` and remove one with `git update-ref -d <ref>`.
