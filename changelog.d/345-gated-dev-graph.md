### Added

- **A shipped graph pairs engine evidence with a human gate: `graphs/gated-dev.yaml`.** It runs one gating lane in a managed worktree: `dev` implements, `e2e` cites `e2e-verify` so the engine runs your `verify_command`, `review` cites `review-style` with the gating check (`CLEAN` or `MINOR:` passes, `FINDINGS:` fails) and one repair round back to `dev`, and then the `approve-publish` gate pauses the run before anything is pushed. The gate's description points to the review and e2e artifacts by path and to the e2e verify record in `state.json`. When review passes, its engine-run `verify` records the HEAD it judged as `refs/omg-approved/<lane branch>`. After you approve, a read-only `check-head` node's engine-run `verify` refuses to continue unless HEAD still matches that ref, then deletes it, so `pr` publishes only the commit the last passing review saw. A missing ref, or a `check-head` that runs again after deleting it, fails. Resume with `oh-my-graph resume <run-id> --approve approve-publish`, or `--reject` to end the run unpublished. A stopped or rejected run leaves its ref behind (`git for-each-ref refs/omg-approved`, `git update-ref -d <ref>`). It does not cite `gated-lane`, because that fragment's `pr` is internal and no gate can sit before it. ([#345](https://github.com/jitokim/oh-my-graph/issues/345))
