### Added

- **`run` warns about a bound input key the graph does not declare, and `auto` about a near miss of one the plan uses.** Each key set by `--input` or `--input-file` that the graph's `inputs:` list does not name gets one warning line naming the key and its winning source (`--input`, or the file that set it last), never the value, with a `did you mean "<name>"?` tail when a declared name is a near miss (Levenshtein distance within 2 for a key of 4 or more runes, within 1 for 3 runes, never for shorter keys). On `run`, a graph with no `inputs:` declares nothing, so every bound key warns, as `lint` already reads it. It is a warning, not a refusal: the key stays bound and the exit status is unchanged. `run` prints it at load, `--dry-run` included, for every undeclared key, since the graph's author declared its inputs and a key outside them is a likely typo. `auto` prints it on the plan screen, `--plan-only` included, only for a near miss: a key within that distance of a name the planned graph declares in `inputs:` or references as `{{ inputs.<name> }}` in any interpolated field, once per key across a goal loop. The planner saw every input and may simply not need one, so `auto "..." --input repo=$PWD` does not warn when the plan uses `repo` itself or no input at all, and a plan that declares and references nothing warns about no key. `state.json` and the run feed (`events.jsonl`) are unchanged. ([#356](https://github.com/jitokim/oh-my-graph/issues/356))
