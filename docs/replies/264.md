### The premise that decides it — @jihoon-lbox

Your table's fourth column is where the argument turns, and the column is wrong for three of the rows' neighbours. The shipped patterns are **not** all prefix-anchored. Three of them are whole-reply pins, anchored at both ends exactly like the planned check node:

So the planned check node is not a class of one that ADR 0019's sweep failed to reach. It is one of **four**, and ADR 0019 enumerated all four by name — `haiku-smoke`'s `write`, the `e2e-verify` fragment, `apply-flags`'s `verify`, and `coordinator.plannedVerdictPattern` — at `docs/adr/0019-no-verdict-anchor-is-relaxed-the-false-fail-is-made-cheap-instead.md:126-130`. > Prefix verdicts get *"anything you need to qualify goes AFTER the verdict, never before it"* — 28 nodes; the four whole-reply pins keep the opposite instruction, *"and nothing else"*.

The caveat clause having nowhere to land on this node is therefore the decision, not the sweep missing a spot. `DESIGN.md:1145-1151` already stated it in those terms and named the same four pins. What was genuinely missing is that `coordinator.go` — the file a reader of `plannedVerdictPattern` actually opens — never pointed at any of that, so the asymmetry read as an oversight. That is what `0f6c4f4` fixes, and your issue is why.

### On your three shapes

**Option 1 (make it prefix-anchored) is refused.** Your own note that "`FAIL` does not start with `PASS`" is correct, but it is not the failure the anchor is holding. A prefix pin passes `PASS` followed by the exception the model wanted to report — and this is the one node class that may not set `success_check.verify` (`validatePlannedNodes`), so that pattern is the whole gate with nothing behind it. That is the relaxation ADR 0019 §3 measured on replayed evidence and refused; relaxing it here would land it precisely where the backstop is thinnest. You are also right that `TestPlannedVerdictPatternMatchesE2EVerifyFragment` (`internal/coordinator/coordinator_test.go:1100`) would drag the fragment along, and right that the fragment has a `verify:` behind it while the planned node does not — which is an argument for keeping the pin here, not for moving it there.

**Option 2 is half-shipped, and I want to be exact about which half.** The planner prompt already tells the node the whole-reply form *and* names the alternative: *"instruct the node that its whole reply is exactly the four bare characters PASS and nothing else, with no markdown emphasis … and no preamble; FAIL otherwise"* (`internal/coordinator/coordinator.go:1667-1670`). That is ADR 0019's "and nothing else" instruction, and it does say FAIL is the other branch. What it does **not** say is your sentence — that a node holding an exception should report `FAIL` *and the exception*, rather than `PASS` with a preamble. "FAIL otherwise" covers the assertion not holding; it does not tell a model what to do with a caveat while the assertion does hold. That gap is real, it is your contribution, and it is listed as not-fixed below rather than claimed as done.

**Option 3 is not built, and the data for it already exists.** A `result_matches` mismatch is already distinguishable at the source: `NodeCheckError.Predicate` (`internal/schedule/errors.go:17`) carries the literal `"result_matches"`, set at `internal/schedule/scheduler.go:1691`. What is missing is a surface that reads it — `runs list` has no such column. So "mark a FAIL whose cause is a string mismatch distinctly from `nonzero_exit`/`verify_failed`" is a display change over a field that is already populated, not a plumbing job. That makes it the cheapest of your three and the one most likely to be picked up.

"All 12 FAILs are `result did not match /^[*_`\s]*PASS[*_`\s]*$/`, not one is a work failure" is a measurement about the pattern's precision in the field, and ADR 0019's *"the false FAIL is made cheap"* was an argument about re-run cost that assumes re-runs happen.
